# iPhone 系統通知基礎驗證

此項任務承接 PR #54 的 iPhone「震動提醒」實機結果：使用者親手開啟原生 switch 時，已感受到觸覺回饋。

## 此階段已處理
- 獨立的 /notification-test 測試頁，不變更個人設定、語音助理、報到或正式時間軸。
- 僅此頁使用的 PWA manifest；iPhone Safari「加入主畫面」後可從圖示進入。
- 獨立範圍的 Service Worker，沒有 fetch 快取、排程、外部通知目標或帳號資料處理。
- 在使用者按鈕動作中請求系統通知權限並顯示固定內容測試通知。
- 處理已拒絕、不支援及尚未加入主畫面的情況，不會自動彈出權限詢問。

## 實機驗收
1. Safari 開 /notification-test，點測試按鈕：提示加入主畫面。
2. 加入主畫面後從圖示開啟（可能需要再次登入）。
3. 點「啟用並顯示系統通知」，允許 iPhone 通知。
4. 檢查通知中心是否出現「夏凱納招待｜通知測試」。
5. 拒絕通知後，會顯示前往設定修正的說明。
6. 測試首頁、報到、語音、個人設定仍正常。

## 尚未實作，不可視為已完成
- Web Push 訂閱與 VAPID 伺服器憑證、資料表、傳送端。
- 鎖屏時由外部事件發送推播；此階段通知是使用者點擊按鈕觸發。
- 任務提前／準點的伺服器排程、重送／去重、作業授權及跨裝置訂閱清理。
- iPhone 震動、聲響的強制保證：最終由系統通知設定、靜音與專注模式控制。

## 下一個開發階段安全要求
- 只在登入者明確同意後存入專屬裝置的 PushSubscription，端點及密鑰只能由本人或受信任的伺服器讀寫。
- 由服務端再查明登入者有權接收的堂次及任務；不得相信瀏覽器傳來的角色／堂次／時間。
- 推播應只有必要資訊，不放手機號碼、憑證或其他同工個資。
- 使用僅限伺服器的 VAPID 私鑰、嚴格授權、去重、失效訂閱刪除及失敗記錄。
- 根據 Asia/Taipei 時區驗證提前提醒及準點提醒，鎖屏及不同裝置交叉測試。
- 在另一個功能分支完成，通過資料庫 RLS 安全測試、Next.js 構建及真機驗收後才評估合併。
