# 服事演練｜開發與驗收規格

狀態：開發草稿。核心時間與資格規則、獨立資料表與管理員交易 RPC 已建立，本次接入管理員 HTTP API 與場次管理卡片。上一輪資料庫 CI 已通過。最新需求取消名單指定，改為所有已啟用總招及管理員自動具備資格；本次更新仍待完整 CI。參與者報到與獨立清單 RPC/API、同工報到及流程介面已撰寫，待最新 CI；語音及演練推播尚未接線，禁止合併。

## 已確認的產品方向

- 同工使用正式註冊帳號、Email 驗證及個人設定，不另建帳號、不給予額外管理員權限。
- 管理員選擇六晚崇、主一堂、主二堂之一作為演練範本，所有已啟用的總招及管理員自動具備參與資格，由管理員按「開始演練」開放，按「結束演練」關閉。沒有預設時長、最低／最高分鐘數或自動到期；最後一項任務完成亦不關閉場次。
- 保留現場 Wi-Fi 報到驗證；正式報到優先，不可同時存在有效正式及演練報到。
- 沿用既有流程頁、提醒設定、語音內容與品牌樣式；僅在有資格且有效時顯示演練入口及「演練中」標示。
- 演練與正式場次、報到、排班、任務完成、訊息及推播紀錄完全分開。註冊、頭像及提醒偏好仍是正式個人設定。
- 本次不做成績、考核、演練報表、專用聊天室或複雜演練排班。

## 第一階段：時間與資格

管理員按開始時以伺服器記錄 startsAt，按結束時記錄 endedAt，未結束即保持開放（每次操作仍需通過帳號、角色及正式報到等安全條件）。不使用 expiresAt 或固定演練時長。複製共用流程的有效任務，按來源時間分組；同時任務保留同組，按 sort_order 排序。演練任務時刻與場次生命週期分離：工程暫定從開始時刻向上對齊分鐘後第六分鐘安排首區塊，後續每兩分鐘安排下一區塊，讓預設五分鐘提前提醒有測試空間，不截斷長流程。此間距只是待驗收的任務排程規則，不是演練時限；可隨後調整。最後區塊後依然可以操作清單、回顧流程，不自動重播或重新排程。使用絕對時間戳，不修改手機時鐘或正式場次。早於開始或錯過發送時間窗的提醒不補發。原始節點 ID 僅作參考，不得當成演練寫入目標。

## 第二階段：資料庫管理基礎（已建立 migration，待重新驗證）

- 新增 service_rehearsals、members、nodes、items、item_states；使用獨立 UUID、外鍵與 RLS，禁止 anon/authenticated 直接存取。暫定同時間只有一個開放中的演練，避免多位管理員重複啟動。成員資料僅記錄實際報到，不預先建立名單；演練中完成帳號審核的總招自動具備資格，角色或帳號停用後失去資格。
- 管理員開始、結束 RPC 皆使用既有 live auth session 檢查及當前角色；整個開始交易複製共用流程及清單快照，不寫正式表。結束可安全重複呼叫，並清除該場次的演練報到欄位。任務狀態寫入只經過 server-only RPC（第三階段）。
- 上一輪隔離 CI 實際由 Supabase CLI 產生 20261126232424_service_rehearsal_foundation.sql 並成功套用。已用該實際檔名放入 migrations，移除臨時 CI 步驟；重新加入測試拆開 volatile 寫入及讀取驗證。無正式資料庫變更。
- 新增管理員 GET 狀態 RPC 與 API 只回傳演練場次、目前可參與人數及報到人數。場次管理頁收合式卡片只需選擇範本、開始、結束及重新整理；取消人員選擇、補加入、撤銷名單。沒有倒數或時長設定，以伺服器開始時間呈現。
- API 僅允許 requireAdmin 加上已驗證登入階段；必須在 Vercel production 且 ENABLE_SERVICE_REHEARSAL=true 才存取演練資料。預覽目前共享正式資料庫，硬性禁止存取。旗標預設關閉，完整驗收及核准前不可啟用；正式環境未配置旗標。

## 第三階段：參與者伺服器端（待驗證）

- `/api/rehearsal` 提供本人的演練狀態、教會網路驗證、報到與個人清單勾選。每次 RPC 核對即時角色、啟用及有效登入階段。未報到只回傳場次，完成報到才提供獨立流程快照；不提供正式任務 ID 或其他同工資料。重複報到及重複清單操作保留原時間。
- 演練寫入使用使用者交易鎖，並對開放場次取得 FOR SHARE，與管理員結束互斥。正式報到表新增狹義 AFTER trigger 使用同一交易鎖，解除此人的演練報到；不改正式資料。正式堂次的可用時間再由 SQL 即時判斷，含總招提早截止與主二提早開放。工作決策：當日已發佈的正式報到由管理員補登（含開放時間外）亦解除演練報到；過往日期的歷史補登不影響。既有正式堂次與正式報到 API 不改。
- 原子交易、角色撤銷、跨場次任務、兩位同工狀態隔離與正式優先測試已加入；真正並行交易壓力測試仍待完成。讀取與寫入需在 UI 使用同一演練 ID，結束或正式報到後清理前端與音訊。
- 管理員及參與者 API 共用 rollout flag；現有預覽仍不可連正式 DB。已接入同工報到及流程分頁，尚未實機驗證。

## 後續：資料庫與伺服器接線（尚未完成）

1. 建立獨立 rehearsal sessions、memberships、task snapshots、task states、device subscriptions、delivery ledger。所有演練寫入使用獨立 UUID 及演練 ID。不得將演練列放入 worship_services、service_assignments、service_check_ins 或正式 checklist states。
2. 管理員開始、結束使用 requireAdmin。參與者狀態及操作使用 requireActiveUser，另核對 live auth session、最新角色、啟用狀態、伺服器時間、實際正式報到。不得接受 client 自述角色、時間、網路或會員身份。
3. 所有演練表啟用 RLS，預設不給 anon/authenticated 直接操作權限；僅伺服器端使用最小範圍授權。快照與報到狀態建立及報到要有原子交易和唯一鍵，正式／演練報到互斥需要在共用交易鎖下實現，不可以僅做先查再寫。
4. 伺服器建立固定演練時間和內容快照，不因管理員後來修改正式流程而改動。使用既有教會網路驗證。管理員結束／帳號停用／正式報到／登入或角色失效均阻止該範圍的新請求及新推播，清除前端狀態與尚未播放的音訊。已交付 OS 的通知無法保證撤回。
5. 資料庫 migration 在獨立本地 Supabase/CI 建立與驗證，禁止預覽環境寫正式 DB。預設關閉 feature flag，待資料庫與應用版本相容、演練實機驗收後才啟用。

## 介面及提醒接線（管理員介面已撰寫，尚待驗證）

- 管理員入口：演練範本、開始／結束、演練中狀態及已進行時間（僅顯示，不是倒數）。不顯示時長選擇或預定結束時間。管理員切頁、登出或重新登入不應自動結束；重新進入可看見尚未結束的場次，防止重複建立。結束需伺服器確認，成功後清理演練狀態，下一次開始建立新的演練 ID。
- 同工首頁：所有已啟用總招及管理員在演練開放且符合其他報到安全條件時顯示服事演練入口；保留正常報到框、現場網路及完成報到後導向流程。避免改變正式六晚崇、主一堂、主二堂的行為。
- 共用流程讀取／渲染，演練操作寫入獨立狀態。不得因使用相同元件而使用正式任務完成 API。
- 語音沿用原有設定、文案與 iOS AudioSession 機制，但需演練專屬授權與絕對時間。提前／準點提醒去重以演練 ID、裝置、區塊及提醒類別為範圍；0 秒提前與準點相同時只播一次。背景震動依即時角色資格與演練報到及當前裝置設定，由伺服器調度，通知文字標示演練。不擴大管理員 preview、正式 push 或一般總招廣播的權限。
- 現有管理員測試是不同的獨立權限功能；不直接移除管理員限制或讓一般總招取得其 API。

## 合併阻擋條件

- 新增功能單元測試、完整 lint、type-check、build、資料庫 RLS/RPC/並行寫入/手動結束與角色撤銷測試、背景推播整合測試全部通過。
- 驗證所有已啟用總招自動具備資格、中途審核啟用、一般同工、未啟用帳號、失效登入、跨使用者/場次、離開教會網路、重複報到、正式報到優先、任意時刻結束、超過 60 分鐘仍開放、最後一項任務完成後仍開放、管理員重新登入後可結束既有演練、再次開始無殘留狀態。
- 至少兩位總招用各自正式帳號在隔離預覽環境同步演練；iPhone 主畫面 Web App、Android 實機分別記錄語音、提前／準點提醒、前景及鎖屏震動、切回 App、關閉提醒及管理員結束後停止。驗證過往正式三堂資料與流程未被修改。
- 實際範本的時間區塊數及內容尚待測試，暫定的任務間距須驗收；長流程不應因時長被裁切。
- 未完成上述項目時 PR 保持 draft；不可合併或宣稱功能可用。

## 第四階段：同工介面（已撰寫，待 CI 與實機）

- 原報到頁標題內顯示「進入演練」，不增加另一套網站或底部導覽項目。點選後沿用報到卡片風格、堂次、Wi-Fi 狀態與重新檢查；成功進入既有流程分頁，保留「進入流程」按鈕。演練資料只使用獨立 API，不操作正式 check-in 或清單。
- 因既有流程渲染器混有正式編輯及寫入邏輯，暫使用同頁內獨立、同品牌的演練渲染內容，清單可勾選、查看任務說明；尚未接入語音、震動、正式流程的所有視覺細節及特殊任務樣式。演練期間先隔離正式語音與管理員測試推播路徑，避免錯播；不更改個人偏好。實機確認前不啟用。
- 伺服器狀態定期重查（未開放 10 秒、已開放 5 秒、報到分頁尚未報到 1 秒，請求完成後才安排下一次）。切回前景及恢復連線重查；正式報到或管理員結束清除演練入口。回到正式報到只切換檢視，不變更正式紀錄。若演練網路失敗則停用操作，重新確認後恢復。
- 前一提交應用 CI 成功，但固定日期的正式報到測試資料違反原有同日報到限制。修正方式只調整隔離測試 fixture 建立順序，不放寬正式 trigger。最新 CI 待確認。

## 第五階段：前景語音與提醒（本次已提交，待 CI）

- 沿用既有 Google TTS、男女聲、文案格式、音訊佇列與 iOS 播放機制。演練 /api/voice 請求帶演練 UUID，伺服器檢查當前報到、即時身份／session／正式報到優先及功能旗標；共享音檔快取仍可使用，但不從手機快取直接繞過演練授權。既有用量控制不變。
- 演練任務以絕對時間戳計算提前／準點（15 秒容許窗、零秒去重、不得補播報到之前的提醒）；首次進入流程為啟動確認＋極簡，手動開啟依偏好播報，外部回來用極簡；App 內切頁不重播。管理員結束、正式優先或連線失敗被前端確認後清空佇列，拒絕過期音檔。伺服器在產生／取快取前及回傳前再次確認。已送到裝置的音檔／通知無法保證零延遲撤回；前景最長輪詢間隔仍為 5 秒（網路耗時另計）。
- 上一輪 SQL CI 通過；應用回歸因防護條件改變原有文字測試而未通過。保留正式條件、更新管理員推播的隔離斷言；新增演練語音時間與授權測試。最新提交尚待 CI 與實機驗收。
- 本階段沒有接入演練震動（前景或背景）、Web Push 或通知派送；不得開啟功能旗標或合併。現有正式推播及管理員測試功能維持原設計。
