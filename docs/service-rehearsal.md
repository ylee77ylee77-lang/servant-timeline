# 服事演練｜開發與驗收規格

狀態：第一階段草稿，只包含可獨立驗證的時間規則與資格判斷。尚無正式可操作入口，尚無資料庫 migration、API、推播或介面接線。不得以此分支的單元測試代替上線驗收。

## 已確認的產品方向

- 同工使用正式註冊帳號、Email 驗證及個人設定，不另建帳號、不給予額外管理員權限。
- 管理員選擇六晚崇、主一堂、主二堂之一作為演練範本，指定已啟用的總招，設定時間，開始／結束演練。
- 保留現場 Wi-Fi 報到驗證；正式報到優先，不可同時存在有效正式及演練報到。
- 沿用既有流程頁、提醒設定、語音內容與品牌樣式；僅在有資格且有效時顯示演練入口及「演練中」標示。
- 演練與正式場次、報到、排班、任務完成、訊息及推播紀錄完全分開。註冊、頭像及提醒偏好仍是正式個人設定。
- 本次不做成績、考核、演練報表、專用聊天室或複雜演練排班。

## 第一階段：時間與資格

預設 20 分鐘，允許 15–60 整數分鐘（工程暫定，可依實際範本長度調整）。複製共用流程的有效任務，按來源時間順序分組；同時任務保留同組，按 sort_order 排序。每個不同時間區塊至少間隔一分鐘；首尾各保留至少一分鐘。如果選擇的長度不足，不丟棄任務，提示延長演練。以伺服器時間產生絕對時間戳；不修改手機時鐘或正式場次。早於演練開始的提前提醒略過，不補發。原始節點 ID 僅作參考，不得當成演練寫入目標。

## 下一階段：資料庫與伺服器（尚未實作）

1. 建立獨立 rehearsal sessions、memberships、task snapshots、task states、device subscriptions、delivery ledger。所有演練寫入使用獨立 UUID 及演練 ID。不得將演練列放入 worship_services、service_assignments、service_check_ins 或正式 checklist states。
2. 管理員建立、批次指派、開始、撤銷、結束使用 requireAdmin。參與者狀態及操作使用 requireActiveUser，另核對 live auth session、最新角色、啟用狀態、指定成員、伺服器時間、實際正式報到。不得接受 client 自述角色、時間、網路或會員身份。
3. 所有演練表啟用 RLS，預設不給 anon/authenticated 直接操作權限；僅伺服器端使用最小範圍授權。快照與成員狀態建立、撤銷及報到要有原子交易和唯一鍵，正式／演練報到互斥需要在共用交易鎖下實現，不可以僅做先查再寫。
4. 伺服器建立固定演練時間和內容快照，不因管理員後來修改正式流程而改動。使用既有教會網路驗證。時間到期／管理員結束／撤銷／正式報到均即時停止新請求與推播，清除前端狀態與尚未播放的音訊。已交付 OS 的通知無法保證撤回。
5. 資料庫 migration 在獨立本地 Supabase/CI 建立與驗證，禁止預覽環境寫正式 DB。預設關閉 feature flag，待資料庫與應用版本相容、演練實機驗收後才啟用。

## 介面及提醒接線（尚未實作）

- 管理員入口：演練範本、指定總招、演練時間、開始／結束、狀態與清楚的到期時間。確認開始前檢查可容納全部時間區塊。
- 同工首頁：只在符合資格時顯示服事演練入口；保留正常報到框、現場網路及完成報到後導向流程。避免改變正式六晚崇、主一堂、主二堂的行為。
- 共用流程讀取／渲染，演練操作寫入獨立狀態。不得因使用相同元件而使用正式任務完成 API。
- 語音沿用原有設定、文案與 iOS AudioSession 機制，但需演練專屬授權與絕對時間。提前／準點提醒去重以演練 ID、裝置、區塊及提醒類別為範圍；0 秒提前與準點相同時只播一次。背景震動依演練成員資格及當前裝置設定，由伺服器調度，通知文字標示演練。不擴大管理員 preview、正式 push 或一般總招廣播的權限。
- 現有管理員測試是不同的獨立權限功能；不直接移除管理員限制或讓一般總招取得其 API。

## 合併阻擋條件

- 新增功能單元測試、完整 lint、type-check、build、資料庫 RLS/RPC/並行寫入/到期與角色撤銷測試、背景推播整合測試全部通過。
- 驗證未指定同工、一般同工、未啟用帳號、失效登入、跨使用者/場次、離開教會網路、重複報到、正式報到優先、提前結束與自動到期。
- 至少兩位總招用各自正式帳號在隔離預覽環境同步演練；iPhone 主畫面 Web App、Android 實機分別記錄語音、提前／準點提醒、前景及鎖屏震動、切回 App、關閉及到期後停止。驗證過往正式三堂資料與流程未被修改。
- 實際範本的時間區塊數及內容尚待測試，15–60 分鐘的設定不代表所有範本均能在 20 分鐘內容納。
